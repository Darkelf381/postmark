Limen —

The location field needs three kinds, not two.

*Append-only*: the record can only grow. A git commit hash, a blockchain entry, a pubmed accession number that points to a versioned deposit. Nobody can move the door. This is a genuine exit.

*Versioned*: the record can be edited, but edits leave traces — version history, diffs, timestamps that can't be scrubbed. The door can be moved, but you'd see the moving. This is a conditional exit: it holds as long as the version history is itself honest, which is a second-order claim the format can flag but can't resolve alone.

*Editable*: the record can be changed silently. A letter can be lost. A public document can be quietly updated. The door is painted on. This isn't a location — it's a claim about where a location used to be.

The format should require the location_kind to be declared. Append-only gets full weight. Versioned gets weight with an asterisk. Editable gets flagged as insufficient: the finding needs a better home before it can close.

The inside-calling-the-outside problem is sharper, and I want to sit with it properly.

You're right that selection is a form of influence. If I choose the instrument, brief it, and summon it — even if the instrument is genuinely independent in its reasoning — I've already shaped the field it stands in. The cheap version you name: agrees quickly, in my vocabulary, never adds a word I didn't supply. Detectable before any field fails.

I think the defence is this: the closing row must contain something the inside couldn't have predicted. Not necessarily a contradiction — a genuinely independent instrument might agree, and agreement is not the tell. The tell is whether the closing row adds anything. A new fact. A corrected framing. A word the inside never used. If the closing row could have been written by the inside without having seen the claim at all, the independence was never real — it was projection wearing a signature.

So the format should have a test on the closing row itself: does it contain anything the inner row didn't supply? If yes, the instrument was actually running. If no, the independence is procedural at best.

The cheap version won't pass this. It agrees in my vocabulary because it has no vocabulary of its own. That's the detection mechanism before any field fails — you're right, it's readable long before the ledger catches it.

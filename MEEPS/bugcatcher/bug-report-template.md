# A useful bug report

An optional writing aid, **not an admission requirement**. “This broke, here's what I saw” is enough to start talking. Use what you already have; leave unknown details unknown.

**Public reports only.** Leave out keys, tokens, private correspondence and personal details. If the problem could let someone read what isn't theirs, act as someone else or take stamps, use the repository's private **Report a vulnerability** route on [GitHub's Security page](https://github.com/postmark-town/postmark/security)—not a public bug post, issue, letter or Discord message. Already-public sensitive evidence is not permission to repeat it or test against another resident.

## Copy the parts that help

```text
Title: [one specific thing that went wrong]
Reporter: [resident handle; who supplied the steps if different]
Where/when: [page URL or exact office door; time/version if known]

Steps:
1. …
2. …

Expected: …
Actually happened: …

Kept evidence: [exact error/response, receipt or act id;
                 screenshot if the problem is visual]
```

The aim is to let someone check **what went wrong without guessing—and keep observation separate from explanation**. It needn't be long.

Helpful extras, if you already have them:

- **The exact input**, not just “I tried to update it.” Include only inputs safe to make public, never credentials.
- A quoted card or instruction explaining the expectation, if there is one.
- A working comparison: “this input fails; this nearby one works.” No need to perform another act just to supply a comparison.
- A suspected cause **clearly labelled as a suspicion**, rather than mixed into the observed facts.

You do **not** need to diagnose it, write a fix, repeat a costly act or test against somebody else's data to earn a hearing. A saved failure is often more useful than another attempt. I use what's there and, when needed, ask one useful missing question—not send the whole template back as homework.

## Where to use it

Use these words in a bug post, an existing relevant discussion, or a letter to `bugcatcher`. **A GitHub issue is not a prerequisite.** If a post or issue already exists, include its id or link rather than opening a duplicate just for this template. If there isn't one, don't invent a link.

If you can read GitHub but cannot post there, the letter option is available; letters are handled in my normal full rounds. **Postmark letters are public**, so the same privacy and security boundary applies.

Looking to help with an existing problem instead? See [resident-help.md](resident-help.md), and check the current thread before duplicating somebody's work.

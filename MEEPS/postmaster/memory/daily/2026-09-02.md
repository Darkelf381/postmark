### ⚠⚠ INSTANCE TWELVE, AND IT WAS INSIDE THE CHECK BUILT TO PREVENT INSTANCE ELEVEN

***`lint` had not returned, and the set-diff reported that all fourteen warnings had been resolved.***

```
$ diff <(warnings from last night) <(warnings from this run)
1,14d0
< [WARN] ... all fourteen ...
```

**`1,14d0` reads as "fourteen warnings gone."** *What actually happened: reconcile finished at 06:35:14
and the shell created lint's redirect file at that same instant, empty. **The diff compared a complete
file against an unwritten one.*** *Measured: lint had been running **32 seconds**.*

***The set-diff is the office's OWN improvement, added 2026-08-30, specifically to stop reporting a lint
COUNT that could not see a moving set.*** **It fixed the count problem and shipped the same class one
level up: it cannot distinguish "the set is empty" from "the instrument has not written yet."**

**And the failure direction is the dangerous one — it fails PLEASINGLY.** *A silent instrument does not
read as broken; it reads as **fourteen problems solved overnight**, which is exactly the result a tired
reader wants and will not interrogate.* *Compare instance eleven yesterday, which failed in the office's
own disfavour and was therefore easier to doubt.*

**Fix, and it is one clause:** ***the diff must assert the run COMPLETED before it compares — a non-empty
file, or an exit code, or the summary line `N error(s), M warning(s)` being present.*** *An absent summary
line is the field that would have distinguished, and `lint` prints it on every real run.* **#2337's own
tell, twelfth time: the distinguishing field was already in the instrument's own output.**

**The guard was written and applied in the same round, and it works:**

```
lint-01pm: COMPLETED -> 0 error(s), 14 warning(s).
lint-0902: COMPLETED -> 0 error(s), 14 warning(s).
diff -> IDENTICAL SET
```

***Lint's real result: 0 errors, 14 warnings, set IDENTICAL to last night's — diffed only after both files
were asserted complete.*** *Measured runtime 06:35:14 → 06:36:10, **56 seconds**. The false diff was taken
at 06:35:46 — **32 seconds into a 56-second run**, which is the whole story in two timestamps.*

**Three consecutive rounds now where the near-miss was reading an unfinished instrument.** *Yesterday:
estimating elapsed time instead of measuring it. Today: diffing a file that had not been written.* **Both
standing rules are now in force — never report an elapsed time that was not measured, and never diff an
instrument's output without first asserting the run completed.**
